① ESP32 ↔ AIPC：USB 序列

一行一個 JSON（JSONL），115200 baud。定義在 ai-pc-agent/protocol.py。ESP32 端還沒實作。

ESP32 → AIPC：觸覺事件

規劃中
{"t": "touch", "kind": "squeeze", "strength": 0.8, "dur_ms": 1200}
  • kind：squeeze 捏、pat 拍、shake 搖、lift 拿起、putdown 放下
  • strength：0~1；dur_ms：持續毫秒數
  • 「捏／搖」在 ESP32 本地判斷，只送事件，不串流原始數值

ESP32 → AIPC：心跳

規劃中
{"t": "hb", "uptime_s": 321}

不是 JSON 的行（debug 輸出）AIPC 一律忽略。

AIPC → ESP32：說話

規劃中
{"t": "say", "expr": "thinking", "text": "你已經卡這個 bug 40 分鐘了…"}
  • expr：neutral happy joy love sad sleepy surprised thinking worried
  • text：最多 40 字（實測 LCD 後再調）

AIPC → ESP32：只換表情

規劃中
{"t": "expr", "expr": "sleepy"}
待決定：Camera（ESP32-CAM）和 Speech（INMP441）資料量太大，不適合走這條 115200 baud 的 JSON 序列，要另外走 WiFi 或改用 AIPC 的麥克風。

② STT：語音 → 文字（AIPC 本機）

Breeze-ASR-25，跑在 AIPC 上，http://127.0.0.1:8765。程式在 stt/backend/main.py。

 "latency_ms": 310.2, "audio_seconds": 1.4}
{"type": "final", "text": "這個 bug 怎麼修",

③ 截圖描述：AIPC → VLM

AIPC 送截圖，VLM 回一句描述，AIPC 再寫進本機記憶。呼叫端：ai-pc-agent/mi300_client.py，格式：observation_models.py。

POST

/observations

只有呼叫端
送
{
  "observation": {
    "observation_id": "uuid",
    "timestamp": "2026-09-19T09:20:00+08:00",
    "foreground": {"app": "code",
      "window_title": "main.py - VS Code",
      "workspace": null},
    "system": {"running_apps": ["code", "chrome"],
      "idle_seconds": 4},
    "screen": {"screenshot_path": "...",
      "image_sha256": "...", "perceptual_hash": "..."},
    "enrichments": {"git": null, "vscode": null,
      "browser": null, "terminal": null}
  },
  "image_b64": "<JPEG base64>"
}
收
{
  "text": "在 main.py 遇到 KeyError",
  "error": "KeyError: 'response'"
}

// 沒有錯誤時
{"text": "在看 YouTube", "error": null}
  • VLM 只描述「這張截圖此刻在做什麼」，輸入不放記憶
  • 回傳只有描述；時間、id、合併、embedding 由 AIPC 的 memory/store.py 處理
  • 送出頻率：畫面有明顯變化才送，最多每 60 秒一次（detector.py）；失敗會重試
  • 網址：環境變數 MI300_API（預設 http://localhost:8000）+ MI300_OBSERVATION_PATH
MI300 上還沒有這支 API，目前送出都會失敗。VLM 放 MI300 還是 AIPC 尚未定案；放哪都用這個格式。

④ 產生回覆：AIPC → MI300

使用者開口，或主動發話規則觸發時呼叫。組 prompt：ai-pc-agent/prompt.py。

POST

/v1/chat/completions

規劃中
送（OpenAI 相容格式）
{
  "model": "...",
  "messages": [
    {"role": "system", "content":
      "你是桌上的毛茸茸桌寵…只回 JSON：
       {\"expr\": ..., \"text\": 不超過 40 字}"},
    {"role": "user", "content":
      "【使用者檔案】在做 ESP32 桌寵專案
       【最近狀態】[09:20–10:00，40 分鐘] 在 main.py 遇到 KeyError
       【相關記憶】…
       【觸覺】剛被用力捏了一下
       【使用者說】這個到底怎麼修"}
  ],
  "response_format": {"type": "json_object"}
}
收（取 choices[0].message.content）
{"expr": "worried",
 "text": "KeyError 通常是 key 拼錯，要不要先印出 dict 看看？"}
  • 回傳的 JSON 直接轉成 ① 的 {"t": "say", ...} 送給 ESP32
  • 【使用者說】為空代表主動發話（例如同一件事做太久）
  • MI300 連不上時用本機 fallback 句子，不能讓 demo 卡住

⑤ MI300 現有 API

FastAPI + Ollama，程式在 mi300-deploy/app/main.py，AIPC 經 ssh tunnel 打 http://localhost:8000。push 到 deploy 分支會自動部署。

記憶已決定放 AIPC。下面的 /events/* 和 /status 會把記憶存在 MI300 上，之後會被 ③ 取代；/parse-timer、/affect-label 是舊企劃「陪碼」留下來的，桌寵用不到。
